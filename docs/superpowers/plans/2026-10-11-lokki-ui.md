# lokki UI Implementation Plan

> **For agentic workers:** execute this plan task by task, in order, with the `superpowers:executing-plans` skill when the seat has the superpowers plugin, otherwise as written. Steps use checkbox (`- [ ]`) syntax for tracking. Every task ends with `cd ui && npm run check && npm test` green and, from Task 6, `npm run e2e` green; the core's suite stays green throughout.

**Goal:** A static web UI, served by the core from `/`, that shows the endpoint, the decision, the accounts and their quota, and edits the settings the API allows, in a plain browser during development and inside the Tauri window later with no change.

**Architecture:** `ui/` is a Vite + Svelte 5 + TypeScript project whose build lands in `core/lokki_core/static/` (gitignored; built in CI and in the app build; `pyproject.toml` already packages `static/**`). One API module (`src/lib/api.ts`) owns the token, the headers, the error envelope and the typed calls; one state module (`src/lib/state.svelte.ts`) owns the polled status and the settings; four views (`Overview`, `Accounts`, `Settings`, `CliProxy`) render from it and call the API through it; `App.svelte` owns the tabs and the token prompt. The UI holds no state beyond the open tab and the token (spec 5): every `PUT` is followed by a `GET`. What the Tauri shell will inject (spec 6.4) is a fetch wrapper that adds the operator header, so the UI sends the header itself only when it holds a token; and one optional hook, `window.lokki.restart(service)`, which the UI calls when present and otherwise replaces with a message.

**Tech Stack:** Node 24 and npm (on the workstation runner's PATH); Svelte 5.57, Vite 8.3, Vitest 5.0, TypeScript 6.0 (what `npm create vite@latest` installs today), `svelte-check`, ESLint 10 with `eslint-plugin-svelte` and `typescript-eslint`; `@testing-library/svelte` 5.4 with jsdom for component tests; `@playwright/test` 1.64 for the one browser run (Chromium rev 1248, which the runner's `~/.cache/ms-playwright` already holds). Versions are pinned exactly in `package.json` (no `^`); `package-lock.json` is committed.

**Why Svelte, in one line (spec 10):** the build is plain JS with no framework runtime to serve or bundle into the PyInstaller sidecar, and four small views need no component ecosystem.

**Spec:** `docs/superpowers/specs/2026-10-10-lokki-app-design.md` section 5 (and 3.4 for the API, 6.4 for what the shell injects, 8 for the layout, 9 for the guard). The API is `docs/app/api.md`, written from the code; sub-project 2's closing facts the UI rests on: rows keyed on `auth_index` (labels shift); before the first read `read_at`/`age_s` are null and `accounts` is empty, and with the mode off the poller never reads; a refresh answers 200 with the previous snapshot when its read failed, `poll.last_error` says why; the ten `decision.reason` strings are exact and `docs/app/api.md` lists them; `PUT /api/settings` answers `{applied, restart_required, comments_dropped}` where a `startup_only` key lands in `restart_required` and not in `applied`.

**Where the plan decides what the spec left open:**

1. The CLIProxyAPI tab in the browser is a link to the panel, opened in a new tab: `cliproxy.url` plus `PANEL_PATH` when `cliproxy.url` is set, else `http://<location.hostname>:<cliproxy.port>` plus `PANEL_PATH` (the page may be reached over a LAN or Tailscale address, and `127.0.0.1` would then point at the viewer's own machine). `PANEL_PATH` is one constant (`"/"` for now) that sub-project 4 sets after checking the pinned release (spec 6.4).
2. Restart after a `startup_only` change: the UI calls `window.lokki.restart("core")` or `("cliproxy")` when the shell defines it, and otherwise shows "restart the core to apply" / "restart CLIProxyAPI to apply". The hook's contract is in `docs/app/ui.md` for sub-project 4.
3. Polling: `/api/status` every 10 s while the page is visible; `/api/accounts` every 30 s on the Accounts tab; nothing while hidden; one fetch at once when the page becomes visible again (`visibilitychange`).
4. The `low_quota.accounts` scope is edited on the Accounts tab as a radio ("every enabled account" = `[]`, "only the checked accounts") plus one checkbox per row; the Settings tab shows the key read-only with a pointer to Accounts.
5. `listen` is edited as one address in Settings (the schema's type is `list`; the API accepts loopback addresses only; the UI sends `[value]`).

## Global Constraints

- The UI never stores the operator token anywhere but `sessionStorage` (key `lokki.token`), with a module-level copy for a page whose storage throws (a private window), and never puts it in a URL. In Tauri no token is stored: the shell's wrapper adds the header, and the UI's own header is absent.
- Every request to the core is same-origin (`fetch("/api/…")`): no base URL, no CORS. In dev, Vite proxies `/api`, `/healthz`, `/version` to the core named by `LOKKI_CORE`, which is required for `npm run dev` (no default: the live relay on this host listens on 8381, and a default would point a developer's browser at production).
- No framework for state: Svelte 5 runes (`$state`, `$derived`) in `.svelte.ts` modules; no store library, no router (four tabs, one `App`).
- Errors are shown as the API's `error.message` (and `error.key` when a `PUT` names one); a 401 shows the token prompt; a 403 shows the API's message (it says whether the token is a client token or the Host/Origin was refused) and the prompt; a network failure says "the core is not answering".
- No secret is logged or rendered except the client key on the explicit copy action, which fetches `?reveal=1` and writes the key to the clipboard without showing it; when `navigator.clipboard` is unavailable (an `http://` address other than localhost) the button is disabled with "copying needs a secure origin; the key is in the settings file".
- Component tests mock `fetch` only (`vi.stubGlobal("fetch", …)`); nothing in the suite reaches a network. The Playwright run starts a real core on a free port with a fake CLIProxyAPI, both under a temp data directory outside the checkout, and stops them; Playwright traces and screenshots stay off (a report would carry the throwaway token).
- Built files (`core/lokki_core/static/`) are never committed; the build never deletes the tracked `static/.gitkeep`; the root `.gitignore` ignores `static/` everywhere, so no `ui/` directory is named `static`.
- Commit messages end with the attribution lines the session carries; `git add` names paths, never `-A`.

## Review Focus

1. A `PUT` of a `startup_only` key (`cliproxy.port`) answers `applied: []`, `restart_required: ["cliproxy.port"]`; the form shows the restart notice and offers the restart only when `window.lokki.restart` exists (Task 4 `test_a_startup_only_key_shows_the_restart_notice`).
2. A 409 from `PUT /api/settings` is shown with the API's `message` and `key`, and the form keeps the user's value (Task 4 `test_a_409_is_shown_with_its_reason`).
3. The scope radio and checkboxes send exactly `{"low_quota": {"accounts": [...]}}` with `[]` for "every enabled account" (Task 3 `test_the_scope_writes_low_quota_accounts`).
4. The copy button never renders the key: it fetches `?reveal=1`, writes the clipboard, and the DOM holds only the masked form (Task 2 `test_copy_reveals_only_to_the_clipboard`).
5. The browser run proves the whole chain: token prompt → Overview from `/api/status` → Accounts rows from a snapshot the real poller read from the fake management API → a scope change written to the file and read back → a 409 (an existing `cliproxy.url` wins over a `cliproxy.port` save) shown with its key (Task 6).

```ts
// One home for how the UI talks to the core: same origin, the operator header
// only when this page holds a token (in the Tauri window the shell's fetch
// wrapper adds it and the page holds none), the API's error envelope as one
// error type. Response shapes follow docs/app/api.md.

const TOKEN_KEY = "lokki.token";
let inMemory: string | null = null;      // the copy for a page whose storage throws (a private window)

export const token = {
  get(): string | null {
    try { return sessionStorage.getItem(TOKEN_KEY) ?? inMemory; } catch { return inMemory; }
  },
  set(t: string | null) {
    inMemory = t;
    try {
      if (t) sessionStorage.setItem(TOKEN_KEY, t);
      else sessionStorage.removeItem(TOKEN_KEY);
    } catch { /* storage refused: the in-memory copy serves this page */ }
  },
};

export type Kind = "auth" | "forbidden" | "refused" | "network" | "other";

export class ApiError extends Error {
  constructor(public status: number, message: string, public kind: Kind, public key?: string) { super(message); }
}

export type Decision = { relay_on: boolean; reason: string; computed_at?: string };
export type Poll = { last_ok_at: number | null; last_error: string | null; reads: number; running: boolean };
export type LowQuota = { enabled: boolean; threshold_percent: number; rule: "all" | "any"; accounts: string[]; poll_seconds: number };
export type Status = {
  revision: string; version: string; started_at: string; uptime_s: number;
  routing: "auto" | "relay" | "direct"; low_quota: LowQuota;
  decision: Decision; poll: Poll;
  runs_since_start: Record<string, number>;
  cliproxy: { url: string; reachable: boolean; version: string | null };
  unknown_keys: string[];
};
export type Endpoint = { urls: string[]; key_masked: string | null; key?: string };
export type SchemaRow = {
  key: string; type: "int" | "float" | "bool" | "str" | "list" | "choice"; default: unknown; meaning: string;
  setting: string; env: string; minimum: number | null; maximum: number | null; choices: string[];
  startup_only: boolean; writable: boolean; secret: boolean;
};
export type SettingsView = Record<string, unknown> & {
  cliproxy: Record<string, unknown>; low_quota: LowQuota;
  env_overrides: string[]; writable: boolean; unknown_keys: string[];
};
export type PutResult = { applied: string[]; restart_required: string[]; comments_dropped: boolean };
export type Account = {
  auth_index: string; label: string; email_masked: string; enabled: boolean;
  used_percent: number | null; remaining_percent: number | null; reset_at: number | null;
  state: "low" | "ok" | "unknown"; error: string | null; in_scope: boolean;
};
export type Accounts = { read_at: number | null; age_s: number | null; accounts: Account[]; decision: Decision; poll: Poll };

type Envelope = { error?: { message?: string }; key?: string };

export async function request<T>(method: string, path: string, body?: unknown): Promise<T> {
  const headers: Record<string, string> = {};
  const t = token.get();
  if (t) headers["X-Relay-Token"] = t;
  if (body !== undefined) headers["Content-Type"] = "application/json";
  let resp: Response;
  try {
    resp = await fetch(path, { method, headers, body: body === undefined ? undefined : JSON.stringify(body) });
  } catch {
    throw new ApiError(0, "the core is not answering", "network");
  }
  const text = await resp.text();
  let parsed: unknown = null;
  if (text) { try { parsed = JSON.parse(text); } catch { parsed = null; } }
  if (resp.ok) return parsed as T;
  const envelope = (parsed ?? {}) as Envelope;
  const message = envelope.error?.message ?? `HTTP ${resp.status}`;
  let kind: Kind = "other";
  if (resp.status === 401) kind = "auth";
  else if (resp.status === 403) kind = "forbidden";
  else if (resp.status === 409 || resp.status === 400) kind = "refused";
  throw new ApiError(resp.status, message, kind, envelope.key);
}

export const getStatus = () => request<Status>("GET", "/api/status");
export const getEndpoint = (reveal = false) => request<Endpoint>("GET", reveal ? "/api/endpoint?reveal=1" : "/api/endpoint");
export const getSchema = () => request<SchemaRow[]>("GET", "/api/schema");
export const getSettings = () => request<SettingsView>("GET", "/api/settings");
export const putSettings = (patch: Record<string, unknown>) => request<PutResult>("PUT", "/api/settings", patch);
export const getAccounts = () => request<Accounts>("GET", "/api/accounts");
export const refreshAccounts = () => request<Accounts>("POST", "/api/accounts/refresh");
```

(`/api/schema` answers `control.schema_listing()`, which is `schema.listing()`: a JSON list of row dicts, each the `Field` dataclass's fields with `choices` a list and a secret's default masked. A refused `PUT` is `core.error_object(...)` plus the top-level `key` the handler adds; its `type` is `server_error` for a 409.)
